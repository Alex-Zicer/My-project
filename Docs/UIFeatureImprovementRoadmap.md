# UI 功能完善计划

## 文档定位

这份文档不再站在“完整商业项目功能规划”的角度，而是改为站在“求职 demo 展示”的角度来整理当前项目。

目标不是继续把系统做大做全，而是把已经实现的内容收束成更适合展示的版本：

- 能在面试里快速讲清楚
- 能录成一段完整演示
- 能体现数据驱动、交互逻辑、UI 实现能力
- 不让系统显得过度设计

当前原则：

- 主线功能优先
- 展示价值优先
- 简洁清晰优先
- 已有复杂扩展层保留，但不作为当前 demo 的重点

---

## Demo 主展示目标

当前项目更适合重点展示 3 类能力：

1. 数据驱动的对话系统
2. 可操作的背包 UI
3. 基础可用的设置与存档界面

这 3 块已经足够支撑一个完整的求职 demo。

## 1. 对话系统

这是当前项目里最适合作为 demo 核心展示点的模块。

### 当前适合重点展示

- 对话图 / 节点结构
- JSON 数据驱动
- 对话数据读取
- 对话触发器
- 对话 UI 展示
- 打字机效果
- 分支选项跳转
- 完整播放流程：
  - 开始对话
  - 显示文本
  - 显示选项
  - 进入下一节点
  - 结束对话

### 当前 demo 应强调的价值

- 不是把对话写死在 Inspector 里，而是使用 JSON 驱动内容
- 支持基本分支逻辑，而不是单纯顺序播文本
- 有完整运行时播放逻辑
- 有专门的 UI 层，而不是临时拼接界面

### 项目中保留但不强调

下面这些能力可以保留在项目中，但不作为当前求职 demo 的主讲内容：

- `DialogueRouterService`
- `DialogueGameStateService`
- 首次 / 重复对话规则
- 剧情状态读写
- `NpcDialogueProfileSO`
- 多数据源里的 SO / CSV 相关扩展能力

保留这些模块的理由：

- 它们对以后做独立游戏仍然有价值
- 它们体现了系统有扩展空间
- 但当前如果作为 demo 主线去强调，会让系统显得过重

### 当前阶段不继续扩展

- 不再把导航系统作为当前重点
- 不再把复杂剧情状态写回作为当前重点
- 不再把复杂 NPC 路由作为当前重点
- 不再把“完整剧情框架能力”作为当前 demo 的完成标准

### 当前阶段完成标准

- 使用 JSON 读取对话数据
- 对话图能完成基础节点跳转
- 能完成一段带分支的对话演示
- UI 层能完整展示说话人、文本、选项和结束流程

---

## 2. 背包系统

背包系统适合作为第二展示点，体现常见游戏 UI 的交互能力。

### 当前适合重点展示

- 背包数据管理
- 分类筛选
- 排序
- 格子列表刷新
- 对象池复用
- 详情面板显示

### 当前阶段补齐主流程

当前阶段只需要把背包补成“可操作”即可，不需要继续做复杂系统。

当前阶段应补齐：

- 选中物品
- 查看详情
- 使用物品
- 装备物品
- 丢弃物品
- 操作后立即刷新数量和界面

### 当前阶段应达到的展示效果

能完整演示下面这条流程：

- 打开背包
- 切换分类
- 选中物品
- 查看详情
- 使用 / 装备 / 丢弃
- 刷新结果
- 关闭背包

### 当前阶段不继续扩展

- 不做拖拽交换
- 不做拆分堆叠
- 不做快捷栏系统
- 不做更复杂的装备体系展示

---

## 3. 设置系统

设置系统的作用不是做复杂，而是体现“基础功能做完整了”。

### 当前适合重点展示

- 音量设置
- 分辨率设置
- 窗口模式设置

### 当前阶段补齐基本可用性

当前阶段只补最基础的可用流程：

- 音量可保存
- 分辨率可保存
- 窗口模式可保存
- 启动后能恢复设置
- 有应用按钮
- 有恢复默认按钮

### 当前阶段不继续扩展

- 不做复杂的显示设置矩阵
- 不做画质等级系统
- 不做高级图形设置

### 当前阶段完成标准

- 设置页可以正常使用
- 重开游戏后设置仍然有效
- 面试演示时能清楚表现“我做了完整设置流程”

---

## 4. 存档界面

存档界面不是当前 demo 的绝对主角，但做出一个基础可见的槽位流程会明显提升完成度。

### 当前适合重点展示

- 存档槽位列表
- 保存
- 读取
- 基础槽位信息展示

### 当前阶段补齐基础槽位流程

当前阶段只需要做到：

- 能看到多个槽位
- 能区分空槽和已存档槽位
- 能显示基本信息：
  - 场景名
  - 存档时间
- 能从界面完成保存和读取

### 与主线模块联动

当前阶段只要保证这些数据能跟着存档恢复：

- 对话主线状态
- 背包状态
- 玩家基础状态

### 当前阶段不继续扩展

- 不做复杂存档摘要
- 不做复杂分类展示
- 不做过多弹窗确认逻辑

---

## 5. 输入与页面管理

这个模块当前只需要“基础可用”，不需要变成一个复杂的导航系统。

### 当前适合保留的基础能力

- 页面打开 / 关闭
- 页面返回
- 对话期间屏蔽背包和暂停冲突
- 背包、暂停、对话之间的基础输入协调
- 默认页面管理逻辑

### 当前阶段只做基础可用

当前阶段只需保证：

- 对话、背包、暂停不会互相抢输入
- 主要页面能正常打开和关闭
- 键盘操作主流程时不会明显冲突

### 当前阶段不继续扩展

- 不做完整导航系统
- 不做手柄 / 键盘焦点精细管理
- 不做复杂按钮状态机
- 不把按钮动效系统作为主展示重点

## 结论

从求职 demo 的角度看，当前项目不需要继续强调“完整框架能力”，而应该强调“已经做出了哪些清晰、完整、可展示的功能模块”。

对话系统应当被收缩成：

- 以 JSON 数据驱动为核心
- 以分支播放流程为主线
- 以 UI 展示能力为亮点

而路由层、剧情状态层、复杂导航层这些内容：

- 可以保留在项目里
- 但不再作为当前 demo 的重点叙事

这样会让整个项目更适合作为求职展示作品，也更容易在面试中讲清楚。
