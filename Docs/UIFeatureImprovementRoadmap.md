# UI 功能完善计划

## 文档定位

这份文档不再站在“继续扩系统”的角度，而是站在“求职 Demo 展示”的角度，整理当前项目已经适合展示的 UI 模块，并明确哪些内容已经够用，哪些只做最小补充。

当前原则：

- 主线功能优先
- 展示价值优先
- 简洁清晰优先
- 能不扩系统就不扩系统

---

## 当前 Demo 主展示目标

当前项目最适合重点展示 4 类能力：

1. 数据驱动的对话系统
2. 可操作的背包 UI
3. 基础可用的设置与存档界面
4. 简化版商店 UI

这几块已经足够支撑一个完整的求职 Demo。

---

## 1. 对话系统

### 当前状态

已完成，可作为当前项目最核心的展示模块。

### 适合重点展示

- 对话图 / 节点结构
- JSON 数据驱动
- 对话数据读取
- 对话触发器
- 对话 UI 展示
- 打字机效果
- 分支选项跳转
- 完整播放流程

### 当前不继续扩展

- 不把复杂剧情路由作为当前重点
- 不把完整剧情状态系统作为当前重点
- 不继续扩展成重型叙事框架

---

## 2. 背包系统

### 当前状态

已基本完成，已经具备完整的可操作闭环。

### 已完成

- 背包数据管理
- 分类筛选
- 排序
- 格子列表刷新
- 对象池复用
- 点击选中
- 选中高亮
- 固定位置详情面板显示
- 统一属性文本格式化
- 操作面板按钮切换
- 丢弃功能
- 出售功能

### 当前演示流程

- 打开背包
- 切换分类
- 选中物品
- 查看详情
- 出售杂物 / 丢弃物品
- 刷新结果
- 关闭背包

### 当前约定

- 列表刷新后清空选中状态，需要玩家重新点击
- 出售当前只支持 `Misc`
- 装备按钮暂时只做展示，不实现装备逻辑

### 当前不继续扩展

- 不做拖拽交换
- 不做拆分堆叠
- 不做快捷栏
- 不做复杂装备系统

---

## 3. 设置系统

### 当前状态

已完成基础可用。

### 已完成

- 音量保存

- 窗口模式保存

## 6. 商店页面

### 当前状态

已完成第一版，可作为补充展示模块。

### 当前设计

- 左侧固定详情面板
- 右侧滚动商品列表
- 详情面板中放购买按钮
- `P` 键打开 / 关闭商店

### 已完成

- 商店格子脚本
- 物品 `buyPrice`
- 商店页面控制器
- 详情面板复用背包脚本
- 购买逻辑
- 当前金额显示
- 玩家输入锁定

### 当前约定

- 商店为无限货源
- 购买后商店列表不减少
- 商店商品通过 Inspector 手动配置

### 当前不继续扩展

- 不做商店库存数据流
- 不做限购
- 不做折扣 / 涨价
- 不做多商人系统

## 当前最适合推进的方向

### 已够用

- 对话系统
- 背包系统
- 设置系统
- 存档界面
- 输入与页面管理

### 可选小补充

- 存档槽显示场景名 / 时间
- 商店页的小型视觉优化
- 背包装备按钮的真实逻辑

### 暂不推进

- 任务系统
- 商店库存系统
- 复杂装备系统
- 更重的 UI 框架扩展

---

## 结论

从求职 Demo 的角度看，当前项目已经不需要继续强调“完整框架能力”，而应该强调：

- 已经做出了清晰、完整、可演示的功能模块
- UI、数据、交互、存档之间已经能形成闭环
- 选择了合适的范围控制，没有把 Demo 扩成过重系统

当前最合适的策略不是继续大扩功能，而是：

- 稳定已有流程
- 做少量展示增强
- 让整套演示路线更顺、更清楚
