# UI 功能完善计划

## 文档目标

这份文档只聚焦一件事：

先把当前项目里的 UI 相关模块补成“基本功能闭环”，让它们先达到可演示、可使用、可继续扩展的状态。

当前阶段暂时不处理：

- 异常提示优化
- 边界情况兜底
- 额外的视觉包装
- 低优先级加分项

也就是说，这一版计划的核心原则是：

- 先把主流程做通
- 先把基础操作做完整
- 先让数据和界面联动起来
- 异常与边界处理放到下一阶段再统一补

---

## 当前阶段范围

当前阶段只做以下 5 个模块的基本功能：

- 对话系统
- 背包系统
- 设置系统
- 存档界面
- 通用输入与页面导航

## 1. 对话系统

### 当前已有

- 已有 `DialogueService` 负责对话流程
- 已有 `DialoguePageController` 负责对话界面显示
- 已有打字机效果
- 已有选项分支显示与点击回调
- 已有 `DialogueTrigger` 触发 NPC 对话
- 已有 `DialogueRouterService` 根据 NPC/Profile 路由不同对话
- 已有 `DialogueGameStateService` 读写剧情状态
- 已有首次 / 重复对话的基础结构
- 已有对话期间锁定玩家输入的处理

### 当前阶段还需实现

#### 1. 对话状态持久化

- 将 `DialogueGameStateService` 的剧情状态接入存档
- 将 `DialogueRouterService` 的首次 / 重复对话进度接入存档
- 保证读档后对话状态仍然正确

#### 2. 对话主流程闭环

- 同一个 NPC 能区分首次对话和重复对话
- 对话完成后能写回剧情状态
- 对话完成后能记录当前对话已播放
- 再次交互时能切到正确的分支

#### 3. 对话输入与导航基础

- 统一继续键和交互键的使用规则
- 选项出现后默认选中第一项
- 键盘 / 手柄可以切换选项
- 对话流程可以不用鼠标完整操作

### 当前阶段完成标准

- 首次对话、重复对话能跑通
- 存档 / 读档后对话阶段不丢失
- 键盘 / 手柄能完整走完一轮对话

---

## 2. 背包系统

### 当前已有

- 已有 `Inventory` 管理背包数据
- 已有添加、移除、排序、分类筛选
- 已有 `BagPageController` 刷新背包界面
- 已有 `BagSlotPool` 做对象池
- 已有 `BagSlotView` 显示图标和数量
- 已有 `DetailedPanelController` 显示悬停详情
- 已有背包打开 / 关闭逻辑
- 已有基础存档支持

### 当前阶段还需实现

#### 1. 从“可查看”变成“可操作”

- 增加选中物品机制
- 增加操作区：
  - 使用
  - 装备
  - 丢弃
  - 取消
- 根据物品类型决定按钮可用性

#### 2. 背包操作闭环

- 选中物品后刷新详情
- 使用物品后刷新数量和列表
- 装备物品后同步背包状态
- 丢弃物品后同步背包状态
- 关闭背包后清空当前选中状态

#### 3. 基础界面状态

- 当前选中格子有高亮
- 空背包有提示
- 空分类有提示
- 不可操作按钮有禁用态

### 当前阶段完成标准

- 背包不只是展示页，而是能完成一轮完整物品操作
- 能完整演示：
  - 打开背包
  - 选中物品
  - 查看详情
  - 使用 / 装备 / 丢弃
  - 刷新结果

## 3. 设置系统

### 当前已有

- 已有音量设置的 Presenter / Model / View 分层
- 音量已通过 `PlayerPrefs` 持久化
- 已有 Master / SFX / BGM 音量调节
- 已有分辨率下拉菜单
- 已有窗口模式切换

### 当前阶段还需实现

#### 1. 画面设置保存

- 分辨率设置接入保存
- 窗口模式接入保存
- 游戏启动时恢复上次设置

#### 2. 基本设置流程

- 增加“应用”按钮
- 增加“取消”按钮
- 增加“恢复默认”按钮

#### 3. 设置页基础体验

- 修改设置后可以明确应用
- 返回设置页时能保持当前值
- 键盘 / 手柄能操作设置项

### 当前阶段完成标准

- 音量、分辨率、窗口模式都可保存
- 重启游戏后设置能恢复
- 设置页具备基本可用性

## 4. 存档界面

### 当前已有

- 已有 `SaveManager`
- 已有保存 / 读取 / 删除底层能力
- 已有固定槽位按钮方式的存读档
- 已有从主菜单进入游戏后读档的流程

### 当前阶段还需实现

#### 1. 从“按钮调用”升级为“存档界面”

- 增加存档槽位列表界面
- 每个槽位显示：
  - 是否为空
  - 存档时间
  - 场景名

#### 2. 基本存读档流程

- 选择槽位保存
- 选择槽位读取
- 覆盖已有存档
- 删除已有存档

#### 3. 与其他模块打通

- 对话状态纳入存档
- 对话进度纳入存档
- 背包状态纳入存档

### 当前阶段完成标准

- 用户可以通过界面完成存档和读档
- 槽位信息清晰可见
- 读档后关键模块状态恢复正确

## 5. 通用输入与页面导航

### 当前已有

- 已有 `UIManager`
- 已有 `BasePageManager`
- 已有 `MainMenuPageManager`
- 已有 `InGamePageManager`
- 已有 `UIPage`
- 已有页面打开 / 关闭 / 返回逻辑
- 已有部分输入冲突处理
- 已有按钮动画触发器

### 当前阶段还需实现

#### 1. 基础输入规则统一

- 统一交互键
- 统一确认键
- 统一返回键
- 统一背包键
- 统一暂停键

#### 2. 基础页面焦点管理

- 页面打开时设置默认焦点
- 页面关闭时恢复上一层焦点
- 动态生成按钮可以参与导航

#### 3. 基础按钮反馈统一

- Hover 状态
- Selected 状态
- Disabled 状态
- Submit / Pressed 状态

### 当前阶段完成标准

- 不依赖鼠标也能操作主要 UI
- 页面切换时焦点不丢
- 对话、背包、暂停之间不会互相抢输入

---

## 结论

这一版计划的重点不是“把所有问题一次做完”，而是先把最核心的 UI 功能做通。

当前阶段的真正目标只有三个：

1. 对话系统先形成完整主流程
2. 背包系统先形成完整操作闭环
3. 设置、存档、输入导航先达到基本可用

等这些基础功能全部落地以后，再进入下一阶段，统一补异常处理和边界优化。
